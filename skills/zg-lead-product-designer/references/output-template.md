# 《引流品设计卡》输出模板

完成设计、诊断或收敛后，按此结构输出。可以根据任务压缩，但不得省略主结果、验收、交付、边界和验证。

## 开头结论

先用一段话说明：

- 最推荐的引流品是什么；
- 推荐它的最大理由；
- 当前最大的待验证风险。

## 1．产品角色

```markdown
引流品名称：
产品形式：
建议价格／决策成本：
交付周期：
后端产品：
它在产品阶梯中的任务：
```

## 2．目标客户与触发场景

```markdown
目标客户：
典型触发场景：
购买前最急的小问题：
不适合的人：
```

## 3．一句话结果承诺

```markdown
帮助【具体人群】，在【明确时间】内，通过【简单机制】，完成【可见成品或动作】，为【下一步业务目标】做好准备。
```

另外写清：客户听得懂的公开表达，以及内部更准确但可能较专业的定义。公开表达优先使用前者。

## 4．最终成品与验收

```markdown
客户最终拿到／完成：
可以拿去做什么：
必须提交的证据：
合格标准：
不合格的典型情况：
第一次成功时刻：
```

## 5．交付闭环

按先后顺序列出：客户输入、关键动作、工具或模板、反馈方式、最终验收。课程型产品按同一成品的进展安排各天，不按“知识模块大全”排课。

## 6．能力证明

```markdown
客户实际体验到的核心能力：
为什么低质量竞争者不容易复制：
与后端产品共享的能力：
```

## 7．标准化与容量

```markdown
固定流程：
客户个性化材料：
人工服务环节：
单客人工时间：
容量上限：
最可能失控的环节：
```

数字未知时保留待测字段，不自行估算成事实。

## 8．自然承接

```markdown
当前产品完整解决：
完成后自然出现的新问题：
后端产品负责：
为什么这是自然升级而不是残缺升单：
```

## 9．承诺边界

明确：不承诺的外部结果、客户必须满足的输入和行动条件、平台或工具限制、需要人工确认的部分。

## 10．候选比较

若存在多个候选，最多保留 3 个，简要展示一票否决、八项评分中的关键差异和推荐理由。没有必要展示机械计算过程时，只给决定性差异。

## 11．最小验证计划

写出测试对象、真实价格、样本规模、周期、核心假设、成功指标、失败阈值、要记录的数据和下一版修改条件。

## 12．最终判断

只使用以下一种：

- **建议进入付费小样本测试**；
- **修改关键结果后再测试**；
- **暂不制作，先补目标客户或后端产品证据**。

结尾给一个最小下一步，不自动继续制作销售页、海报、PPT或课程资产。
