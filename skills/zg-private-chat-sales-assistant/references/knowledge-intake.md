# 知识接入与初始化

本文件用于首次使用、切换产品或发现知识不足时。目标是用最小必要信息让助手理解业务，不把用户困在长问卷里。

## 资料优先级

按以下顺序使用资料：

1. 用户本轮明确提供、且说明为当前有效的信息。
2. 用户指定的产品知识库、产品卡、客户画像和正式规则。
3. 经用户确认的客户案例、聊天记录和 FAQ。
4. 历史材料，仅作参考；与当前资料冲突时使用更新版本。
5. 助手推断，只能标为假设，不能写进对外话术当成事实。

## 有知识库时

请用户提供文件、文件夹、项目、链接或可访问的知识库入口。只读取当前产品需要的内容，优先检索：

- 产品名称、定位和核心结果。
- 目标客户、适用条件和不适用条件。
- 交付内容、周期、形式和价格。
- 真实案例、客户反馈和证据边界。
- 常见问题、退款规则、合同和服务边界。
- 品牌语气或历史私聊样本。

读取后先形成一份简短的“已知业务底稿”，让用户纠正明显错误。不要把读取到的旧优惠、旧价格或宣传案例自动当成当前有效事实。

## 没有知识库时

第一次只收集两张卡。用户可以自由描述，不要求逐题回答；助手负责整理并指出关键缺口。

### 产品卡

```text

一句话解决的问题：
主要适用人群：
不适用人群：
客户购买前通常处于什么状态：
交付内容与流程：
周期和参与要求：
价格、付款方式与当前有效条件：
与其他方案的主要差异：
已有真实案例或过程证据：
可以承诺什么：
不能承诺什么：
退款、试用、合同或售后规则：
```

### 目标客户画像卡

```text
客户是谁：
常见身份、行业或业务阶段：
正在经历的具体问题：
最希望获得的变化：
过去尝试过什么：
为什么过去没有解决：
购买时最看重什么：
最常见的疑虑：
谁参与最终决策：
他们平时会怎样描述这些问题：
哪些表达会让他们反感：
```

## 建议补充的两张证据卡

核心信息完成后，再按需补充，不要阻塞第一次使用。

### 案例与证据卡

```text
客户背景：
原始问题：

实际参与过程：
发生了什么可核实变化：
统计周期：
证据形式：
哪些结果不能归因于本产品：
是否获准公开或私聊使用：
```

### 沟通风格卡

```text
希望给客户什么感受：
常用称呼：

通常一条消息多长：
喜欢或避免使用的词：

```

## 初始化回复模板

知识不足时：

> 在给具体消疑话术前，我需要先知道你卖什么、卖给谁，否则只能生成通用话术。你可以直接把产品知识库或资料发给我；如果暂时没有，就先告诉我两件事：产品解决什么问题，以及最主要的目标客户是谁。我会边用边帮你补齐。

知识已经足够时：

> 我已经了解这个产品的目标客户、交付、价格、证据和承诺边界。现在请把客户的准确原话以及前后几轮聊天发给我；如果只有一句原话也可以，我会先给保守判断。

## 知识充分度检查

- **可直接工作**：产品、客户、交付和价格清楚，至少有一种真实证据或明确边界。
- **可保守工作**：知道产品和客户，但案例或政策不足；只能给澄清与方向性回复。
- **必须补充**：不知道卖什么、卖给谁，或者需要引用某项效果、优惠、保证却没有依据。
